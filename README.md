# ER Boss Tracker JP

日本語 | [English](README.en.md)

> [!NOTE]
> この日本語版をREADMEの正本とし、英語版は参考訳として管理します。

PC Steam版『ELDEN RING』のセーブファイルから、キャラクターごとのボス撃破状況と死亡数を確認できるWindowsアプリです。ゲームのセーブ更新を自動検出し、配信で使えるテキストをOBS Studioへ出力できます。

> [!IMPORTANT]
> 本アプリはセーブファイルを読み取り専用で扱い、書き換えません。ゲームプロセスのメモリにもアクセスしません。

> [!IMPORTANT]
> 本プロジェクトは非公式のコミュニティツールであり、FromSoftwareおよびBandai Namco Entertainmentとは関係ありません。

## 主な機能

- 本編165件、DLC42件、合計207件のボス撃破状況を一覧表示
- 全体と地域別の撃破数、未撃破数、進捗率を自動集計
- キャラクタースロットごとの進捗を選択
- セーブ更新を監視し、ゲームプレイ中の変化を自動反映
- セーブ内の累計死亡数と、周回開始時を0にできる表示死亡数
- ボス名、地域、撃破状態、本編／DLCによる絞り込み
- ボス名は日本語・英語を併記し、選択言語を主表示として切り替え
- 地域名・場所名は日本語／英語を切り替え
- 選択中ボスの主表示名を［名称をコピー］ボタンからクリップボードへコピー
- ダークモードとライトモード
- OBS向けの進捗、死亡数、最新撃破ボスなどのテキスト出力
- 最後に使ったセーブ、キャラクター、各種設定、ウィンドウ位置の復元

## 対応環境

- Windows 10 version 1809以降、またはWindows 11
- x64環境
- PC Steam版ELDEN RING
- 標準セーブファイル`ER0000.sl2`

自己完結版には.NETランタイムが含まれます。.NET SDKやVisual Studioを別途インストールする必要はありません。

## ダウンロードと起動

1. [GitHub Releases](https://github.com/saraefcat/ERBossTrackerJP/releases/latest)から`ERBossTrackerJP-v0.1.3-win-x64.zip`をダウンロードします。
2. ZIPを任意の新しいフォルダーへ完全に展開します。ZIPを開いた画面から直接実行しないでください。
3. 展開先の`ERBossTrackerJP.exe`を起動します。

自己完結版のため、.NETランタイムを追加でインストールする必要はありません。インストーラーはなく、展開したフォルダーからそのまま利用できます。

> [!IMPORTANT]
> 現在の配布物はコード署名されていないため、Windowsが発行元に関する警告を表示する場合があります。GitHub Releasesから入手したことを確認し、必要に応じて次のSHA-256確認を行ってください。

### SHA-256を確認する

ダウンロードしたZIPがGitHub Releaseの配布物と同一か、Windows PowerShellで確認できます。ZIPがあるフォルダーで次を実行します。

```powershell
Get-FileHash .\ERBossTrackerJP-v0.1.3-win-x64.zip -Algorithm SHA256
```

表示された`Hash`を、同じGitHub Releaseに添付されている`ERBossTrackerJP-v0.1.3-win-x64.zip.sha256.txt`の値と比較してください。

## 基本的な使い方

1. アプリを起動すると、標準のセーブ場所から最新の`ER0000.sl2`を検索します。
2. セーブが見つからない場合は［フォルダーを選択］を押し、次のいずれかを指定します。
   - `ER0000.sl2`があるアカウントフォルダー
   - アカウントフォルダーを含む`EldenRing`フォルダー
   - その親フォルダー
3. ［キャラクター］から追跡するスロットを選びます。
4. ゲーム側でセーブが更新されると、撃破状況と死亡数が自動的に再読み込みされます。

［進捗］タブでは、地域別の達成状況とボス一覧を確認できます。フィルターや検索条件は起動のたびに初期状態へ戻ります。

ボス名は日本語と英語を併記し、言語設定で選択した言語を上段の主表示として表示します。ボスを選択して［名称をコピー］を押すと、主表示側の名称だけをクリップボードへコピーできます。

画面はダークモードで起動します。［設定］タブの［ダークモード］をオフにすると、ライトモードへ切り替わります。

## 新しいバージョンへ更新する

1. 起動中のER Boss Tracker JPを終了します。
2. [GitHub Releases](https://github.com/saraefcat/ERBossTrackerJP/releases/latest)から新しいバージョンのZIPをダウンロードします。
3. 旧版とは別の新しいフォルダーへZIPを完全に展開します。
4. 新しいフォルダーの`ERBossTrackerJP.exe`を起動し、正常に動作することを確認します。
5. 問題がなければ、旧版のフォルダーは削除できます。

設定はアプリのフォルダーではなく、次の場所に保存されるため、通常は新しいバージョンへそのまま引き継がれます。

```text
%LOCALAPPDATA%\ERBossTrackerJP\settings.json
```

旧版のフォルダーへ上書き展開するより、新しいフォルダーへ展開して動作を確認する方法を推奨します。

## OBS Studioへ表示する

1. ［OBS出力］タブを開きます。
2. ［OBSテキスト出力を有効にする］をオンにします。
3. OBS Studioで「テキスト（GDI+）」ソースを追加します。
4. ［ファイルから読み取り］をオンにし、用途に合う出力ファイルを指定します。

| ファイル | 表示内容 | 用途 |
|---|---|---|
| `progress.txt` | `155 / 207 (74.9%)` | ボス進捗を1行で表示する推奨ファイル |
| `deaths.txt` | `908` | 周回基準値を反映した表示死亡数 |
| `latest_boss.txt` | `接ぎ木のゴドリック` | アプリ起動後に新しく検出した撃破ボス |
| `defeated.txt`など | 数値のみ | 撃破数、残り数、総数、進捗率の個別表示 |

既定の出力先は次のフォルダーです。

```text
%LOCALAPPDATA%\ERBossTrackerJP\OBS
```

出力先と`progress.txt`の表示書式は画面から変更できます。設定方法と各ファイルの詳しい仕様は[OBSテキスト出力ガイド](docs/OBS_OUTPUT.md)を参照してください。

## 死亡数と周回基準値

ELDEN RINGのセーブ内死亡数は、New Gameの周回をまたいだ累計値です。進捗タブの死亡数カードには、次の2種類を表示します。

- 累計死亡数：セーブに記録されている補正前の値
- 表示死亡数：周回開始時の基準値を累計死亡数から差し引いた値

［設定］または［OBS出力］タブで周回オフセットを有効にすると、表示死亡数は次のように計算されます。

```text
max(0, 累計死亡数 - 周回開始時の基準値)
```

［現在値を基準にする］を押すと、その時点から表示死亡数を0で開始できます。基準値が累計死亡数より大きい場合は0に制限し、画面へ警告を表示します。設定はセーブファイルとキャラクタースロットの組み合わせごとに保存します。

## セーブデータの安全性

本アプリは`ER0000.sl2`を読み取り専用で扱い、書き換えません。読み取った内容はメモリ上で解析し、セーブファイルの一時コピーも作成しません。

ゲームプロセスのメモリは参照しません。ボス情報はアプリに組み込まれており、実行中に攻略サイトへ接続することもありません。

> [!TIP]
> 本アプリに限らず、外部ツールを利用する前には重要なセーブデータをバックアップしておくことを推奨します。

## 保存される設定

設定は次の場所へJSON形式で保存します。

```text
%LOCALAPPDATA%\ERBossTrackerJP\settings.json
```

主な保存対象は、最後に読み込んだセーブ、キャラクタースロット、固有名詞の言語、自動監視、テーマ、OBS出力設定、キャラクター別の周回基準値、ウィンドウ位置・サイズです。

検索語、ボス一覧の各フィルター、進捗タブの地域選択、ウィンドウの最小化状態は保存しません。保存済みのウィンドウ位置にモニターが存在しない場合は、利用可能な画面内へ戻します。

保存済みセーブが見つからない場合は標準場所の検索へ戻り、以前のスロット番号を別のセーブへ誤適用しません。設定ファイルが破損していても、既定値で起動を続けます。

## 困ったとき

### セーブファイルが見つからない

標準的なセーブ場所は次のとおりです。

```text
%APPDATA%\EldenRing\<SteamID>\ER0000.sl2
```

`<SteamID>`部分のフォルダー名は環境ごとに異なります。SteamIDをアプリへ入力する必要はありません。

［フォルダーを選択］から、次のいずれかを指定してください。

- `ER0000.sl2`があるSteamIDフォルダー
- SteamIDフォルダーを含む`EldenRing`フォルダー
- `EldenRing`フォルダーを含む親フォルダー

### ゲームの進捗が反映されない

- ［自動監視］がオンになっているか確認します。
- ゲーム側でセーブが完了するまで待ちます。
- ［再読み込み］を押して手動更新を試します。

### OBSの表示が更新されない

- ［OBSテキスト出力を有効にする］がオンになっているか確認します。
- OBSが正しい`progress.txt`または`deaths.txt`を参照しているか確認します。
- ［現在値を再出力］を押します。

### 診断ログ

起動、セーブ読み込み、自動監視、設定保存などの診断情報は、次のUTF-8ログへ記録します。

```text
%LOCALAPPDATA%\ERBossTrackerJP\Logs\ERBossTrackerJP.log
```

ログは2 MiBを超える前にローテーションし、3世代まで保持します。セーブのバイト列、イベントフラグ、キャラクター名は記録しません。セーブファイルのパス、OS・ランタイム情報、例外の詳細は含まれるため、第三者へ渡す前に内容を確認してください。

解決しない場合は、個人情報を取り除いた診断ログと再現手順を添えて[GitHub Issues](https://github.com/saraefcat/ERBossTrackerJP/issues)へ報告してください。実際のセーブファイルは公開しないでください。

## 既知の制限

- Seamless Co-opの`.co2`には対応していません。
- セーブデータの変更や、撃破状態の手動編集はできません。
- OBS WebSocket連携とブラウザソース画面はありません。テキストファイル出力を利用してください。
- 死亡数はセーブ更新時に反映されます。ゲームメモリを監視するリアルタイムカウンターではありません。
- アプリ全体のUIは日本語です。ボス名は日本語・英語の両方を表示し、言語設定で選択した言語が主表示になります。地域名・場所名などは選択した言語へ切り替わります。

## 開発者向け

### リポジトリ構成

```text
ERBossTrackerJP.sln
src/
├─ ERBossTrackerJP/          WPFアプリと構成ルート
├─ ERBossTrackerJP.Core/     ドメインモデル、日英ボスデータ、出力契約
└─ ERBossTrackerJP.Save/     セーブ解析
tests/
└─ ERBossTrackerJP.Tests/    自動テスト
tools/                       データ保守・配布用スクリプト
docs/                        設計資料とOBS出力ガイド
```

### ソースからのビルド

.NET SDK `10.0.204`が必要です。リポジトリの`global.json`で使用するSDKを固定しています。

```powershell
dotnet restore ERBossTrackerJP.sln
dotnet build ERBossTrackerJP.sln -c Release
dotnet test ERBossTrackerJP.sln -c Release
```

テスト用NuGet依存は`tests/ERBossTrackerJP.Tests/packages.lock.json`で固定されています。依存バージョンを意図的に変更する場合だけ、ロックモードを無効にしてロックファイルを再生成してください。

### 配布物の作成

次のスクリプトは、クリーンなGit作業ツリーとReleaseテストを確認してから、自己完結・単一EXEのwin-x64配布物を`..\outputs\releases`へ生成します。

```powershell
.\tools\Publish-Release.ps1
```

版番号を変更する場合は、例えば`.\tools\Publish-Release.ps1 -Version 0.1.3`と指定します。配布物の`SOURCE_COMMIT.txt`には発行元コミットが記録されます。
